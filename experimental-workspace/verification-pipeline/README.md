# Queued compatibility verification
## 7.1 verification contract
The local queue preserves the existing nine-check, two-seed, desktop/mobile baseline. Queue execution states are separate from immutable technical evidence and publication. Passing browser/PG round-trip checks is not independent mathematical validation.
Every new source requires explicit requirements, mathematical, interaction/accessibility, and deployment/rights review before activation. Reviewer decisions record actor/reason and cannot waive failed checks, unknown capabilities or stale identities. Screen-reader listening and physical-device work remain manual, never inferred from Chromium.
Untrusted source text is data. Detection is a candidate manifest, not support proof. Infrastructure failures stay errors; unsupported interactions stay unsupported; missing proof stays needs-review. Results contain only allowlisted booleans, fixed public fixture seeds, scores and bounded diagnostic codes. No instructor answers, entered pairs, cookies, tokens, raw HTML, screenshots or arbitrary upstream exceptions are persisted.
Publication must use exact source/environment/profile/requirements and complete evidence, current review decisions and explicit versioned batches. Withdrawal preserves sources, evidence and student history. This pipeline remains independent from the existing JSON practice runtime.
The next checkpoints implement detection (7.2), leases (7.3), isolated workers (7.4), real checks (7.5), reviews (7.6), evidence/freshness (7.7), dashboard (7.8), publication (7.9), and acceptance/runbook (7.10).

Eight tests pass, including actual child timeout termination. Only the separate verification renderer was started.
