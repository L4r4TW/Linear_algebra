- Validate Compose changes with docker compose config and docker compose up --build -d --wait. Run powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./smoke-renderer.ps1 for renderer changes; it checks rendering, grading, and session restoration.
- The smoke check's instructor answer map is for local diagnostics only. Future student APIs must allowlist problem files, keep privileged parameters server-side, and accept grading only from PG.
- Verify the pinned renderer's API implementation and actual responses before adding integration code.

- Maintain workspace/server/exercise-catalog.json as the indexed metadata catalog; the compatibility gate derives the playable allowlist. Use stable unique IDs; keep PG paths in server code and return only friendly summaries to clients. Index only real OPL entries with source attribution; enable only currently verified entries in an active batch. Verification seeds are fixtures, not the future session seed policy.

- Use workspace/server/renderer-client.mjs for exercise loading. Keep renderer configuration, catalog paths, error causes, and session tokens server-side. Validate client changes with docker compose exec -T workspace npm test and npm run smoke:renderer-client inside that container.

- Use exercise-sessions.mjs to generate and persist session IDs, seeds, and renderer tokens. Resume through the stored token; never silently regenerate a failed session. Session JSON belongs only in /data/sessions on the named Docker volume. Run npm run smoke:sessions inside the workspace container for persistence changes. HTTP sessions enforce anonymous browser ownership using a HttpOnly cookie and a stored token hash. Unowned CLI records must never be exposed through HTTP. Supabase account ownership is still required before account-based deployment.

- API routes live in workspace/server/http-app.mjs. POST /api/sessions accepts only exerciseId; never forward caller renderer parameters. Project only the PG problem wrapper to API HTML, never the renderer form or JWT inputs. Maintain same-origin checks, strict body validation, friendly errors, and owner verification. Run npm test and npm run smoke:api inside the workspace container for API changes.

- The picker is in workspace/public. Preserve loading/empty/error states, URL-based session restoration, and cookie ownership. Keep PG HTML inside the sandboxed frame without allow-same-origin or form permissions. Use the MathJax proxy and the reviewed opaque asset registry in exercise-assets.mjs; never add a client-selected URL/path proxy. Follow [ASSET_LOADING.md](ASSET_LOADING.md) for approved dependencies, pins, and capability handling. Verify new PG widget types separately. - Answer collection uses answer-fields.js and answer-bridge.js inside workspace/public. The narrow widget-answers.js adapter handles mapped GraphTool value notifications, feedback, and focus; preserve its native getter/setter semantics, helper exclusions, and cleanup. Read [WIDGET_VERIFICATION.md](WIDGET_VERIFICATION.md) before adding adapters. Preserve exact names/values and ordered duplicate-name pairs, exclude renderer/helper fields, and keep snapshots session-bound. Use collectCurrentAnswers for fresh values before future grading. Maintain source/origin/channel/request checks, revision ordering, timeout cleanup, and bridge destruction when replacing frames. Never treat client field names as a backend allowlist.

- Grading uses POST /api/sessions/:id/answers with only an answers array of ordered string pairs. Verify ownership before PG requests. Derive the field contract from restored server-trusted HTML, never a client manifest. Preserve valid duplicate names, reject scalar duplicates/reserved fields, clear missing answers, and atomically advance saved tokens. The submission guard supports one Node process only. Validate changes with npm test and npm run smoke:grading inside the workspace container; instructor answers belong only to operator diagnostics.

- Persist lastSubmission and submissionCount atomically with the updated renderer tokens. Keep exact submitted pairs, server-derived fieldNames, server timestamps, PG score, and canonical student PG feedback strings together. Preserve legacy token-only records; never invent historical submissions. API submission snapshots are owner-only and must not include renderer tokens. Validate state changes with smoke:submission-state, smoke:grading, and the grading/refresh browser check; retain the latest snapshot only until a dedicated history store is implemented.

- Practice controls in picker.js submit fresh ordered pairs through the owned grading endpoint. Lock before answer collection, prevent repeat submissions, and never automatically retry a grade. Keep the live frame and inputs intact on failure and while awaiting the response. Clear/abort pending browser work on frame replacement and ignore late results. Preserve native keyboard button activation, mobile sizing, live status/error messages, and the browser checks for failure, duplicates, and navigation.

- Student field feedback is projected only from the configured renderer response JWT.answer score.answers; never accept a browser grading token or return correct answers/claims. PG error_message can contain mathematical hints: use explicit error flags or a missing parsed student_value with an error to identify invalid syntax. Parsed wrong-coordinate hints remain mathematical errors. Persist the safe fieldFeedback snapshot, preserve legacy snapshots, respect suppressed individual grades, and follow [FEEDBACK_PRESENTATION.md](FEEDBACK_PRESENTATION.md) for canonical text plus reviewed notation. Preserve frame message authentication, aria-describedby/aria-invalid, changed-since-check handling, and the real mixed-feedback/refresh browser test.

- Enter submission is limited to eligible single-line answer inputs. Preserve multiline/native widget keys, modifiers, repeats, IME composition/key code 229, and explicit opt-outs. Route shortcuts and focus commands only through the authenticated opaque-frame bridge and retain the parent submission guard. Manage focus only if there has been no intervening user interaction; keep return-to-answer navigation and cross-frame focus outlines visible. Use the dedicated live region for state transitions, not per-keystroke result announcements. Reference stale-result descriptions only when visible. Retain assistive MathML, narrow-screen touch targets, forced colors, reduced motion, and the accessibility browser checks. Automated semantic checks do not replace an actual screen-reader listening review.

- Complete-flow verification is documented in PRACTICE_VERIFICATION.md and automated by verify-practice.ps1. Preserve the browser ownership and accepted-but-lost-response tests. The optional renderer outage check force-stops only the renderer and restores it in finally; keep cookies/private data in memory. Preserve the Compose startup PID cleanup and exec: stale script/hypnotoad.pid caused a confirmed false-hot-reload failure (exit 140) after restart. Do not remove volumes to recover the renderer. ## Compatibility work

- Keep `compatibility/catalog.json` separate from `workspace/server/exercise-catalog.json`. Operator artifacts must not become public routes. Only the six deliberately promoted, capability-verified batch members become student-allowed IDs; the other five fixtures remain blocked. Preserve the privacy/allowlist tests.
- Use the actual exported `problemHtml` projection, frame builder, collector, bridge, and server answer contract in comparisons. Host the full official reference in a same-origin iframe as its editor expects; a bare page fails its upstream `window.frameElement.id` assumption.
- Follow `compatibility/README.md` for pinned source hashes, two-seed probes, paired browser checks, and temporary screenshots. Commit only sanitized observations, never raw renderer HTML, cookies, JWTs, expected values, or instructor answer maps. The positive scaffold diagnostic may use expected values only in memory.
- The controlled loader now supplies the tested static/generated images, GraphTool dependencies/icons, and scaffold toggles. Scaffold content updates and full widget acceptance remain outstanding. Preserve opaque capability redaction in QA observations, script/defer order, GraphTool help-only ephemeral storage, and fail-closed resource errors. The picker keeps its original live frame after grading even when PG returns new fields. Reconcile that lifecycle deliberately while preserving unsaved edits, bridge/session identity, focus, and saved tokens.
- A matching score or native field-name set does not prove usable rendering. Require full owned-session grading, feedback, refresh, keyboard, and narrow-screen checks before promoting candidates. The observed matrix uses nine legacy numeric fields; compound matrix evaluators remain unverified.

- Operator widget acceptance uses server-only exerciseLookup/exerciseList factory injection in a temporary HTTP application. Keep those defaults tied to the real approved catalog; never accept lookup functions, paths, instructor flags, or verification settings from HTTP clients. Positive fixtures and bounded choice calibration belong only to compatibility/widget-acceptance.mjs. Preserve sanitized reports and the explicit scaffold refresh/relock limitation.

Require exact source identity, current runtime/profile evidence, every seed/viewport check, no observed limitation and an explicit active batch. Keep failed/disabled evidence and sessions intact. ## Draft persistence

Read [DRAFT_PERSISTENCE.md](DRAFT_PERSISTENCE.md). Keep tab drafts separate from server-saved graded attempts, bound to session/exercise/field contract, and restore only after ownership is confirmed. Preserve ordered duplicate-name pairs and explicitly cleared groups. Drafts override only a matching checked baseline (or a reconciled pending attempt); unrelated newer checked results win. Preserve edits made during grading and show stale feedback. Never claim successful autosave after storage failure, expose draft records in public responses/logs, or grant storage/same-origin permission to the iframe. Draft implementation changes require browser draft checks and renewed runtime compatibility evidence.

## Session recovery

Follow [SESSION_RECOVERY.md](SESSION_RECOVERY.md). Preserve structured safe API codes and exact saved-session identity. Classify expired/rejected renderer tokens only from the verified bounded structured upstream errors on stored-token requests; never infer expiry from generic HTTP failures or message substrings. Internally distinguish ownership, but publicly mask missing and unowned sessions identically. Terminal failures keep records/drafts and do not offer a repeated-token loop. Ambiguous grading blocks another check until an explicit GET reload, preserving live edits through pending/failed recovery and blocked storage. Keep the frame until an owned matching response and a fresh answer snapshot are ready. Never regenerate seeds, replace tokens, delete records or start another exercise as an error fallback.

## Feedback model

Follow [FEEDBACK_MODEL.md](FEEDBACK_MODEL.md). Use PG's aggregate score directly and bind individual feedback by generated field name. Preserve parser-versus-mathematical-error evidence, coherent status/score pairs and explicit ungraded reasons. Suppression is server-controlled: persist the policy with the token/snapshot, redact both public score locations and grading messages, and keep a neutral UI through refresh and draft restoration. Never infer correctness from a withheld raw PG score. Keep old feedback tied to the checked pairs, remove stale invalid semantics on edit, and restore them on exact revert without grading. Run the real-PG feedback audit and the full compatibility gate after runtime changes. The additional suppression fixture remains private; it is not student-approved.

Read [FEEDBACK_PRESENTATION.md](FEEDBACK_PRESENTATION.md) before changing message projection or typography. Never insert PG feedback HTML or auto-typeset an entire message. Preserve the shared TeX allowlist/budgets, fixed pinned library loading, literal fallback, suppression, late-render guards and legacy string snapshots. Only PG-authored messages and grade-based generic guidance are student feedback; never derive an explanation from instructor answers. The source-pinned equation-feedback fixture is operator-only. Keep feedback CSS limited to app-owned message/math wrappers, preserving widget geometry and MathJax SVG/assistive output.
