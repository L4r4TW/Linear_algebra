## Working behavior

- [x] **Keep exercise identity.** A session generates one seed, stores PG tokens and restores via the saved token. The browser's `?session=` URL restores the same session, not another random version. Failed restoration does not silently call start. Evidence: fresh six-entry audit; [exercise-sessions.mjs](workspace/server/exercise-sessions.mjs); existing seeded `seedPreserved` checks.
- [x] **Restore the latest successful check.** Updated renderer tokens, the exact submitted answer pairs, submission count/time, overall PG score, field statuses/messages and summary/message are persisted atomically. Refresh restores them without regrading. Evidence: fresh audit; [submission-state.mjs](workspace/server/submission-state.mjs); session/server tests.
- [x] **Collect the supported answer types.** Generated names, repeated-name checkbox values and field grouping are preserved. Server-restored HTML supplies the trusted answer contract. Native choice feedback belongs to the group rather than being inserted into each choice label. Evidence: existing seeded collection checks and field-feedback browser tests.
- [x] **Separate blank, invalid and mathematically incorrect answers.** Explicit PG error flags or a null parsed `student_value` with an error determine invalid syntax; message wording is not used as a classifier. Mathematical hints in `error_message` with a parsed value remain incorrect, not invalid. Evidence: fresh five-entry text-field checks; [grading-feedback.mjs](workspace/server/grading-feedback.mjs) and tests. This is scoped to tested evaluators, not every PG macro.
- [x] **Show supported PG feedback safely.** Field `ans_message`/`error_message` and overall `summary`/`msg` are projected to text. Correct-answer claims and privileged tokens are excluded. If PG provides no field explanation, the UI supplies a generic status explanation rather than inventing mathematical advice. The fresh samples produced parser messages on all five text exercises, but no field message for their valid-but-wrong numeric attempts. See [renderer-client.mjs](workspace/server/renderer-client.mjs) and [field-feedback.js](workspace/public/field-feedback.js).
- [x] **Show partial results and stale feedback.** Overall partial score, field status and changed-since-check labels exist. Editing after a check preserves the old result but marks it as describing the previous submission. Mixed/partial outcomes are evidenced for multi-answer exercises; not every single-answer evaluator supports partial credit.
- [x] **Retry a check without losing live inputs.** Collection/submission locks prevent duplicate clicks in the current page. Failed checks keep the frame and edits. There is no automatic grade retry; editing and pressing Check answer again uses the same session. Browser controls unlock after failure.
- [x] **Retry a transient load failure without rerolling.** The fresh fake-503 check passed for all six. Required-resource recovery, accepted-but-lost grading responses and ownership were covered in the existing regression/browser suites; they were not recreated in full here.
- [x] **Protect ownership and withdrawn exercises.** Other browsers cannot load or grade an owned record. Catalog withdrawal blocks start/restore/grade while retaining records; server tests confirm no renderer access or record deletion. Missing and unowned sessions intentionally share a 404 to avoid disclosing another user's session.
- [x] **Provide existing keyboard/announcement hooks.** Check answer, Return to answers, inline alerts, a polite status region, focus routing and Enter for eligible single-line fields are implemented. Existing seeded keyboard/mobile evidence covers the six entries; actual assistive-technology listening remains manual.

## Recommended implementation order

Implement durable drafts and their restoration precedence first. Then add failure categories and uncertain-submission reconciliation. Establish feedback/suppression rules before rendering richer feedback or authored hints. Add result-area move-on controls with draft protection, then run the full continuity/recovery/accessibility matrix. Keep existing six-entry eligibility unchanged until a runtime change has matching new compatibility evidence.

## Reproduce the focused audit

Start the ordinary Compose services first. Run from `experimental-workspace/`:

```powershell
docker build -f compatibility/Dockerfile -t linear-algebra-compatibility-qa .
$continuityArtifacts = Join-Path $env:TEMP ('continuity-audit-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $continuityArtifacts | Out-Null
docker run --rm --network linear-algebra-experimental_default --shm-size=1g --mount "type=bind,source=$continuityArtifacts,target=/artifacts" linear-algebra-compatibility-qa node compatibility/continuity-audit.mjs
docker compose exec -T workspace npm test
docker compose exec -T workspace node server/check-catalog.mjs
```

The audit creates normal anonymous owned sessions in the existing session volume, as ordinary practice does. It does not remove volumes, mutate existing sessions, stop the renderer or use instructor answers. Its known-wrong constants/parser inputs are operator samples, never committed observations. Review/sanitize the JSON before replacing the checked-in audit evidence. Rebuild the QA image after script changes. This focused audit does not approve new catalog entries or replace the seeded compatibility gate.
